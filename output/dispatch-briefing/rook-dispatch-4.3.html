01 · What we found

Misses rose after the reply window shrank

4.2 cut the wait from 90 to 60 seconds and increased the weight of travel time so nearby responders would get more first offers.

Support and interviews

03 · Root cause in the code

A timeout could reduce future opportunities

  1. Offer expires
    Dispatch waits 60 seconds.
    offer.py:42
  2. Score drops
    4.2 counts the miss like a refusal and deducts 0.12.
    offer.py:30
  3. Rank can fall
    Future callouts reuse that history score.
    routing.py:40
  4. Fewer chances to recover
    A higher-ranked responder can accept first. Scores do not recover with time.
    history.py:20

The code and simulation confirm the mechanism. Its contribution to individual production outcomes is still uncertain.

04 · Implemented in the course code

4.3 deducts points only for an explicit refusal

Five simulated misses from a score of 0.50

4.2 · 0.50 → 0.38 → 0.26 → 0.14 → 0.02 → 0.00
Backup ranks first on the next callout.
4.3 · 0.50 → 0.50 → 0.50 → 0.50 → 0.50 → 0.50
Original responder ranks first and accepts the next callout.
The patch is prevention-only. Existing scores carry forward because verified starting scores were unavailable.
